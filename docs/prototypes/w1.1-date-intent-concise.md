# W1.1：动态日期、auto 联网识别、联网回答简洁化 — 最小规格

- 基线：`feature/w1-web-grounded-answer` @ `6b3e430`（已在 Lab 通过验收）
- 分支 / worktree：实现授权时新建（建议 `feature/w1.1-date-intent`，基于 `6b3e430`）
- 角色：Claude 设计与审查，Codex 实现。不部署、不 push、不 merge。

## 1. 要解决的 W1 实测问题

1. 模型不知道当前日期。W1 的回答里出现了与证据不符的时效断言（"Python 3.14 尚未发布"）。代码中所有系统提示都不含日期。
2. `auto` 模式漏判。"What are the main new features in Node.js 22?" 没有触发联网，模型凭记忆回答且有错误。
3. 联网回答偏长。实测一个回答生成 1,411 token，约 22 秒，主要耗时就在生成上。

## 2. 实施边界

| 项 | 改动位置 | 不改 |
|---|---|---|
| 动态日期 | `app/conversation_runtime.py`：在 `system_prompt = system_prompt_fn()` 之后、语音注释之前，追加一段日期说明 | **不改 `personality/`**（Personality 开发线在 `main` 上并行进行，避免冲突） |
| auto 识别 | `app/web_intent_gate.py` 的 `_WEB_PATTERNS` 新增规则 | 判定顺序（NO_WEB → WEB → 模型）、模型提示、`decide_web_intent` 接口 |
| 简洁回答 | `app/web_evidence_prompt.py::WEB_EVIDENCE_SYSTEM_INSTRUCTION` 追加一句 | 证据打包格式、引用规则 |

### 2.1 动态日期

- `process_turn` 新增可注入参数 `now_fn`，默认值为 `datetime.now(runtime_config.TIMEZONE)`，**每个请求都调用一次，不缓存、不写死**。
- 时区来自 `CORVUS_TIMEZONE`（IANA 名称，默认 `America/Los_Angeles`），启动时校验，非法值直接报错。**不从主机系统时区推断。**
- 追加的文本（英文，一行）：`Current date: YYYY-MM-DD (Weekday), UTC±HH:MM. Use it to judge recency. When web evidence is supplied, prefer it over your training knowledge about what is current; do not claim something is unreleased or latest unless evidence supports it.`
- 普通聊天、Vision、语音轮次都会带上这段，开销约 40 token。不新增模型调用，也不写入任何持久化数据。

### 2.2 auto 联网识别

新增两类确定性规则，都要求“发布 / 特性词”和“具体对象或时效词”**同时出现**，避免误判普通聊天：

- 发布 / 特性词：EN `new features?|what'?s new|release notes?|changelog|released?|release date|latest version`；ZH `新特性|新功能|更新了什么|有什么新|有哪些新|发布日期|什么时候发布|最新版本|版本号|更新日志|发行说明`。
- 同时满足以下任一项：
  - 一个 ASCII 标识符（如 `Node.js`、`Python`、`macOS`）或版本号（`\d+(\.\d+)*`）；
  - 时效词（`最新|最近|今年|current|latest|this year`）。

NO_WEB 规则仍然最先判定（如“不要联网”、记忆类问题）。不满足上述规则的问题仍然交给原有的模型判定。

### 2.3 简洁回答

在 `WEB_EVIDENCE_SYSTEM_INSTRUCTION` 末尾追加：`Be concise: lead with the direct answer, then only the key supporting points; unless the user asks for detail, stay within about 300 words (or about 500 Chinese characters). Never drop a needed fact or its citation to save space.`

## 4. 最小验收

### 关键失败（出现任意一项即不通过，其他项通过也不能抵消）

- 明显需要实时信息的问题在 `auto` 下没有联网（见下方 A1–A3）。
- 普通闲聊、或问 Corvus 自身的问题在 `auto` 下被判为联网（A4–A6）。
- 回答中的日期或时效断言与注入的日期、或与引用证据矛盾。
- 引用编造、来源 URL 编造、模型调用重复、消息写入重复。
- 回归测试出现新增失败。
